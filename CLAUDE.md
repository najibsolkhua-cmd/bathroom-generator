# Памятка проекта для Claude

Конструктор ванной комнаты для сайта строительной компании. Клиент загружает фото своей ванной, за 5 шагов выбирает параметры и может дописать пожелания; сервер проверяет «только ванные», генерирует 5 вариантов (gpt-image-2 / gpt-image-2.5), ставит водяной знак; клиент выбирает вариант и заказывает замер. Подробно — docs/generation.md.

Общаться с владельцем проекта, писать комментарии в коде и сообщения коммитов — на русском.

## Структура

- `public/` — сайт (HTML/CSS/JS без сборки). Эта папка публикуется на GitHub Pages.
  - `index.html` — разметка; блок `APP_CONFIG` в начале — название компании, телефон, адрес сервера.
  - `css/style.css` — стили. Цвета и шрифты заданы переменными в `:root`.
  - `js/options.js` — шаги и варианты в фильтрах (что видит клиент). Читается и браузером, и сервером.
  - `js/guard-rules.js` — стоп-правила для свободного запроса. Читается и браузером, и сервером.
  - `js/app.js` — логика страницы: пошаговый конструктор, фото, сводка, анимация загрузки, галерея, просмотр, заказ замера, три режима работы.
  - `img/photos/` — примеры с Unsplash (`<стиль>-1..5.jpg` и `-sm.jpg`), `img/watermark.png` — водяной знак.
  - `fonts/` — шрифты Onest и Unbounded (локально, без Google).
  - `preview.html` — сайт на компьютере и телефоне рядом; `credits.html` — ссылки на фото; `privacy.html` — шаблон политики.
- `server.js` — сервер на встроенных модулях Node.js 20+.
- `lib/prompt.js` — промпт для генерации (на английском), проверка параметров и ограничения по площади.
- `lib/guard.js` — проверка нейросетью: фото — это ванная, пожелания только про ванную, результат — ванная без людей и надписей.
- `docs/` — как устроена генерация (`generation.md`) и откуда фильтры (`filters.md`).
- `assets/photos.json` — список фото Unsplash; при изменении GitHub Actions сам скачивает их (`assets-fetch.yml`).
- `scripts/check-options.js` — сверяет варианты в `options.js` и `lib/prompt.js`.
- `deploy/` — настройки Nginx и systemd для VPS reg.ru.
- `.github/workflows/pages.yml` — публикация `public/` на GitHub Pages.

## Правила

- **Никаких внешних npm-пакетов.** Сервер работает на чистом Node.js, `npm install` не нужен. Не добавлять зависимости без явной просьбы владельца.
- **Ключи и токены только в `.env`**, который не попадает в git. Никогда не коммитить ключи, не вставлять их в `public/`.
- **Генератор рисует только ванные и санузлы.** Свободный запрос клиента (до 300 символов) проходит правила `guard-rules.js` и проверку `lib/guard.js`; в промпт попадает только проверенный английский перевод, не исходный текст. Не добавлять новые текстовые поля в обход этих проверок.
- **Водяной знак на каждой картинке**: на сервере — ImageMagick, на сайте — `.wm` поверх картинки, если знак не впечатан.
- **В каждом фильтре первый пункт — «Подберём сами» (id `auto`)**, выбран по умолчанию: клиент проходит шаги одной кнопкой «Далее». В мультивыборе `auto` исключает остальные пункты. Новые группы — тоже с `auto`.
- **Замер — только по выбранным вариантам.** Клиент выбирает один или несколько; без варианта кнопка неактивна и сервер отклоняет заявку (`imageIndexes`).
- **Варианты фильтров меняются в двух местах**: `public/js/options.js` (русские названия) и `TEXT` в `lib/prompt.js` (описание для нейросети). После правки — `node scripts/check-options.js`.
- **Демо-режим на GitHub Pages должен работать без сервера.** Не ломать ветку `state.mode === 'demo'` в `app.js` (там примеры из `img/photos/`).
- Фото — только с лицензией, разрешающей коммерческое использование (Unsplash), и со ссылкой в `credits.html`.
- Тексты интерфейса: простые слова, без канцелярита, кнопка называет действие («Показать 5 вариантов», «Отправить заявку»).

## Проверка перед отправкой

```bash
node --check server.js && node --check public/js/app.js && node scripts/check-options.js
MOCK=1 PORT=3000 node server.js   # открыть http://localhost:3000 и пройти сценарий
```

Для изменений интерфейса — пройти сценарий в браузере на ширине 1440 и 390 px: фото → 5 шагов → генерация → галерея → просмотр → заказ замера. Проверить блокировку пожеланий (например, «кухня», «собака»).

## Публикация

- Любой push в `main` запускает GitHub Actions: папка `public/` публикуется на https://najibsolkhua-cmd.github.io/bathroom-generator/ примерно за минуту.
- Там сайт работает в демо-режиме (примеры фото вместо генерации, заявки не отправляются); текст плашки — «Демо-режим Solk: …» в `index.html`.
- Боевой сайт — на VPS reg.ru, обновляется командой из README («Обновить сайт после изменений»).

## Как вносить правки

- Мелкие правки (тексты, цвета, варианты фильтров, исправления) — сразу в `main`.
- Крупные изменения (новые функции, переделка сервера) — в отдельной ветке и через pull request, чтобы владелец посмотрел перед слиянием.
